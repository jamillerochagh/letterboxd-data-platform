# Letterboxd Data Platform

An end-to-end data platform that transforms raw Letterboxd exports into enriched movie analytics, taste profiles, audience comparisons, and personalized recommendations.

The project combines data ingestion, external API enrichment, PostgreSQL caching, analytical processing, and an interactive Streamlit application.

## Live Application

Try the deployed application:

https://letterboxd-data-platform.streamlit.app

Export your Letterboxd data as a ZIP file and upload it directly to the application.

## Project Overview

Letterboxd allows users to export their account data, but the export contains limited movie metadata.

This project builds a data pipeline around that raw export and enriches it with data from TMDB.

The resulting dataset powers:

- viewing activity analytics
- movie taste profiling
- genre, director, country, language, runtime, and decade analysis
- personal ratings vs TMDB audience ratings
- personalized movie recommendations
- searchable movie history

## Data Pipeline

### 1. Ingestion

Users upload the original ZIP export generated by Letterboxd.

The application extracts and processes datasets such as:

- watched movies
- ratings
- diary entries
- reviews
- likes

Each upload is processed independently and identified using a SHA-256 fingerprint during the application session.

### 2. TMDB Enrichment

Letterboxd exports do not contain enough metadata for deeper analysis.

Movies are enriched using the TMDB API with attributes including:

- TMDB ID
- director
- primary and secondary genres
- production country
- original language
- runtime
- TMDB audience rating
- popularity
- poster
- tagline
- overview

### 3. PostgreSQL Cache

To avoid unnecessary API requests, enriched movie metadata is stored in a shared PostgreSQL cache hosted on Supabase.

Before requesting metadata from TMDB, the pipeline checks whether the movie already exists in the database.

```text
Movie
  |
  v
PostgreSQL cache
  |
  +-- found ------> reuse metadata
  |
  +-- not found --> TMDB API
                       |
                       v
                  enrich movie
                       |
                       v
                  cache result
```

The database acts as an optimization layer rather than a critical dependency. If the cache is unavailable, the application can continue processing movies through TMDB.

### 4. Analytics Layer

The enriched data is transformed with pandas to generate analytical views including:

- viewing activity over time
- most watched genres
- most watched directors
- genre combinations
- runtime distribution
- movies by decade
- countries and languages explored
- highest and lowest rated movies
- rating behavior by genre and director

### 5. Taste Profiling

The application builds a content-based taste profile using signals from the user's movie history.

The profile considers:

- genres
- directors
- countries
- languages
- decades
- ratings
- likes

Higher-rated and liked movies contribute more strongly to the resulting profile.

### 6. Recommendation Engine

Candidate movies are discovered through TMDB and compared against the user's taste profile.

Each candidate receives a weighted similarity score based on multiple content attributes.

```text
User History
     |
     v
Taste Profile
     |
     +-- Genres
     +-- Directors
     +-- Countries
     +-- Languages
     +-- Decades
     |
     v
Candidate Movies
     |
     v
Weighted Similarity
     |
     v
Taste Score (0-100)
     |
     v
Ranked Recommendations
```

Movies already watched by the user are removed before the final ranking.

The Taste Score is a content-based heuristic and should not be interpreted as a probability.

## Application Features

### Overview

Provides a summary of the user's Letterboxd activity, including:

- movies watched
- estimated hours watched
- average rating
- liked movies
- reviews
- rewatches
- viewing activity over time

### Your Taste

Explores the user's movie preferences through genres, directors, decades, countries, languages, runtimes, and rating behavior.

### You vs Crowd

Compares personal Letterboxd ratings with TMDB audience ratings to identify:

- overall rating differences
- genre-level differences
- movies where the user disagrees most with the crowd
- movies rated substantially higher or lower than the TMDB audience

### Recommendations

Generates personalized movie recommendations using the content-based taste profile.

Recommendations include:

- Taste Score
- TMDB rating
- movie posters
- hidden gems
- highly rated safe bets
- directors worth discovering

### History

Provides a searchable and filterable view of the user's complete movie history.

Users can filter movies by:

- title or director
- genre
- country
- release year
- personal rating

## Database Schema

TMDB movie metadata is cached in the `raw.movies` PostgreSQL table.

Core fields include:

```text
tmdb_id
title
release_year
director
genre_primary
genre_secondary
genre_tertiary
country_primary
original_language
runtime_min
vote_average
popularity

```

`tmdb_id` is used as the unique movie identifier for cached TMDB records.

## Running Locally

Clone the repository:

```bash
git clone https://github.com/jamillerochagh/letterboxd-data-platform.git
cd letterboxd-data-platform
```

Create and activate a virtual environment:

```bash
python -m venv .venv
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Create a `.env` file based on `.env.example` and configure the required environment variables.

Example:

```env
TMDB_API_KEY=your_tmdb_api_key
DATABASE_URL=your_postgresql_connection_string
```

Run the application:

```bash
streamlit run app/app.py
```

## Security

Credentials and user data are excluded from version control.

The repository ignores:

- `.env` files
- Streamlit secrets
- uploaded Letterboxd exports
- local datasets
- temporary files
- database credentials

Production credentials are configured using Streamlit Secrets.

Uploaded Letterboxd exports are processed by the application and are not committed to the repository.

## Engineering Decisions

### Shared metadata cache

Movie metadata is reusable across users. Storing enriched TMDB records in PostgreSQL reduces duplicate external API requests and improves processing efficiency as the cache grows.

### Graceful database degradation

The PostgreSQL layer is treated as a performance optimization rather than a hard dependency.

If the database cache becomes unavailable, the pipeline can continue enriching movies through TMDB instead of failing the user's analysis.

### Separation of raw and enriched data

Letterboxd account information and external movie metadata are processed separately before being combined for analytics.

This keeps ingestion logic independent from external enrichment logic.

### Session-level upload fingerprinting

Uploaded ZIP files are hashed using SHA-256 so Streamlit can determine when a new dataset has been provided and invalidate session-level analytical results accordingly.
